Bot performance: original vs current

Actual graphics-enabled Unity 6.3 Editor runs on this laptop. Three maps × 0/16/32 bots plus a 32-bot tsunami per map, repeated for original and optimized code. Same seed, normal bot movement and physics, identical navigation-ready warmup, no video recording or fixed capture clock. Memory sampled every 5 seconds, block activity every second. This is desktop Editor evidence, not standalone or Quest performance.

Only the eight bot/rig optimization files are reverted for the original run; all other game content stays constant. Jaguar appearance stays current in both versions because these scenarios contain no enemy actors. The main project was not changed. Two pre-existing Unity processes remain open and their CPU activity is retained in telemetry. Percent differences are observed single-pair differences, not proven repeatable gains. Collapse, bot travel and wave-progress mismatches are flagged below.

What this establishes

24 FPS cases completed; zero runtime errors. The optimized run also passed 16 geometry regression checks and 120 objective-contract assertions. Memory was healthy in both variants: before minimum 25.7 GiB available / 21.9 GiB commit headroom, after minimum 25.2 GiB available / 21.6 GiB commit headroom.

Original Castle observed roughly 7–11% higher FPS, but its no-bot control also improved 7.5%; this single pair does not establish that the bot optimizations caused that entire gain. Festival City at 16 bots was essentially unchanged. The current 32-bot tower partially collapsed while its original-code counterpart stayed asleep; Festival City also had different block activity. Those comparisons are real gameplay outcomes but do not isolate CPU efficiency.

Healthy memory did not remove the large-map stress bottleneck. The current Festival tsunami run averaged 4.6 FPS with a 1.35-second P95 frame time. Geometry sampling still improved in the dedicated microbenchmark: tower 8.534→4.829 ms (43.4% less), Festival 5.971→4.035 ms (32.4% less), with identical sampled points. These savings are narrower than whole-game FPS.

Brain-command timing in the raw output covers injected wrappers that survive the sample; respawns can replace a wrapper. It is not a complete per-bot CPU total. Physics and other native profiler markers are inclusive and may overlap. The scenario labelled calm means no disaster was started; ordinary bot interactions can still collapse structures.
