# Short scramble / cling

Hold Space (desktop), right A (controllers), or right pinch (tracked hands) near a steep crate for 0.18 seconds. Movement becomes wall-relative: forward/back climb up/down, left/right shimmy. With bare hands, left pinch supplies upward intent. Release to drop. Moving up to a clear ledge starts the existing vault. The view stays upright and remains under the player's control.

Grip lasts about four seconds of movement, or 4.7 seconds hanging idle. It refills only after 0.45 seconds on grippy, slowly moving ground. Switching crates or briefly releasing does not refill it. Exhaustion/violent release imposes a cooldown and requires releasing the control before catching again. Desktop and headset HUDs show remaining grip.

Only registered CastleBlock survivor surfaces are climbable, between 55 and 100 degrees. Floors and ceilings are excluded. Gentle block motion carries the climber using local contact coordinates and swept CharacterController movement, without parenting, rigidbody joints, or forces applied to crates. Climbing detects the source dynamic body's point velocity, angular velocity, acceleration, and abrupt pose changes; the kinematic collision proxy does not conceal a throw.

Seam handling searches a bounded nearby hand-span, with a default of 0.35 human-scale metres (0.175 world metres at the current half-size player). Angled probes search adjacent faces through 67.5 degrees; high probes and an outward ray retreat detect small overhanging courses before the capsule strikes their underside. Every continuation requires a real reachable crate face. There is no blind hanging grace, stamina refill, collision bypass or teleport across a gap. Large openings and violently moving blocks still break grip. The `seams` validation request checks small gaps and the actual alternating cardinal/diagonal keep layout alongside the observer camera.

Defaults break grip above 5.5 m/s point speed, 2.5 m/s downward speed, 1.8 rad/s spin or 22 m/s² acceleration. Release inherits bounded block velocity and a small outward separation. Other fast moving blocks encountered by the controller can also break grip. `ApplyTraversalImpulse(Vector3 velocityChange)` exposes the detach/knockback path for a future impact or ragdoll system. This does not implement a full ragdoll simulation.

Configuration is on CastleSurvivor under Short scramble / cling. Implementation is isolated in CastleSurvivor.Climbing.cs. `Simulate(input, jumpPressed, dt, climbHeld)` works for humans or external drivers; CastleBotCommand.climbHeld lets future bot traversal adapters request it. Existing bot planning is unchanged. Shared CandyPlayerAvatar presents alternating wall contacts and blends back to live hands on release; network systems that transmit LastFrame inherit that visible pose.

Validation: after compilation, put `climb` in ArtDirection/SlopeChecks.request in Edit Mode. CastleClimbChecks exercises the actual controller and crate proxy in isolated runtime fixtures; reports are written to ArtDirection/ClimbChecks.txt. The scene is never saved by the tests. Put `run` in the same request file for the slope regression checks.

Design references: Catlike Coding, Movement/Climbing (wall-relative controls, moving contacts, upright view): https://catlikecoding.com/unity/tutorials/movement/climbing/ ; Ubisoft, Immortals Fenyx Rising / 6 Things (finite climbing stamina): https://news.ubisoft.com/en-us/article/7aH5iI0QqsS46XcN5zqXcI/immortals-fenyx-rising-6-things-you-need-to-know . Motion breakaway thresholds and the short shared grip budget are specific tuning choices for this physics castle.
