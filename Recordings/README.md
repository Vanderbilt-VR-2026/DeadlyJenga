# Match recordings

Open **Tools → Deadly Jenga → Record Matches** in Unity. The window imports the current lobby or local match settings, including map, mode, movement, game rules, player population, bot presets, AI hands and disaster tuning. Use **Use current lobby / match settings** to refresh the draft. Changing the mode loads its default rules; changing the map keeps the selected mode.

Choose iterations, duration and FPS, then start. Each iteration opens a fresh Game scene, applies the saved settings after Unity resets static state, verifies the requested population/map/mode, captures four spectator views and encodes an MP4. Player slots include one local observer; 51 slots means 50 survivor bots. Its body remains in the match, as in normal spectator mode. **Rotate views (seconds)** defaults to 15 and cycles all four cameras through the population; set it to zero to keep fixed targets. This gives coverage of defenders and active travellers without selecting only successful bots. Capture resolution follows Game View; keep its size fixed while recording. Videos contain no audio. Video FPS controls saved frames; the simulation runs at a whole-number multiple of that rate, at least 60 updates per second. A 15 FPS video therefore samples every fourth simulation update rather than slowing bot thinking to 15 updates per second.

FFmpeg must be installed on each machine. The window finds it on PATH, or you can choose its executable. The choice is saved locally, not in the repository. No Unity package is required.

Each batch and video uses local date/time to the second, for example `2026-10-20_19-30-45/2026-10-20_19-31-00/2026-10-20_19-31-00.mp4`. A numeric suffix prevents overwrites if names collide. Each video has its settings, actual match details, target labels, result and encoder log alongside it. `simulation.txt` records simulation/video cadence, and `bots.csv` records each bot's action, movement state, stationary reason, position, speed, planner age, recovery count and objective once per video second. Batch status and results are saved in `status.txt` and `batch.json`. Validation summaries go to `Logs/Validation/SpectatorRecording.txt`.

The completion popup and system sound run after encoding finishes. You can close the recording window while a batch runs; reopen it to see progress or cancel. Cancellation keeps completed videos and partial frames. Successful recordings remove temporary JPEGs unless **Keep source frames** is selected. Failed runs keep their frames and logs; the queue can continue to the next iteration. Recording stalls time out after two minutes; encoding times out after ten minutes.

A disconnected local session is required. Starting stops existing local Play Mode; the original scene setup and match choices are restored at the end, but the previous running match is not resumed. Unsaved edit-mode scenes must be saved or explicitly discarded in Unity's save prompt. The recorder never saves gameplay scenes or prefabs.

Videos and generated files are ignored by Git. This README, the folder ignore rules and the DevTools recorder are shared with the team. Copy or upload individual recordings separately when needed.

For a terminal launch, open Unity with `-executeMethod DeadlyJenga.DevTools.Editor.SpectatorVideoCapture.Run`. Optional arguments: `-captureBots 50 -captureMode ctf -captureMap mode-ctf -captureIterations 3 -captureSeconds 30 -captureOutput <absolute folder>`. The command-line version exits its Unity process; it cannot open a second Editor on a project already open in Unity. For full settings, pass `-capturePlan <JSON file>` using a batch's saved `settings.json` as the format. The window keeps the Editor open.

**Tools → Deadly Jenga → Validation → Check Recording Queue** runs targeted integration checks for settings import, repeated CTF runs, cancellation, scene restoration and recovery after a deliberately induced FFmpeg input failure. These are short real Play Mode recordings; their output goes in `Recordings/Validation`, and the report goes in `Logs/Validation/SpectatorRecordingChecks.txt`.

Scripts can also use an already-open Editor: copy a saved batch `settings.json` to `Logs/Validation/SpectatorRecording.request.json`. Write a temporary file and rename it into place so Unity reads the complete JSON. The recorder consumes the request when idle and ready, applies the same validation as the window, and writes `SpectatorRecording.request-result.txt` beside it. Existing batches finish before a queued request starts. The window shows the running batch's actual requested settings. A `Logs/Validation/SpectatorRecording.cancel` file cancels the active batch.
